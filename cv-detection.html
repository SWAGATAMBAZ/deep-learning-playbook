Bounding boxes and IoU

🧒 In plain English

A detector draws rectangles. To grade one, ask "how much does my rectangle overlap the true one?" IoU (Intersection over Union) is that overlap as a fraction: 1 means perfect, 0 means they don't touch. A prediction usually counts as correct when IoU ≥ 0.5.

📐 IoU
IoU = area(A ∩ B) / area(A ∪ B) = inter / (areaA + areaB − inter)

Box formats trip people up: xyxy (corners, used by torchvision), xywh (top-left + size, COCO), cxcywh normalised to 0–1 (YOLO label files). Mixing them up is the #1 cause of "my mAP is zero".

Box-regression losses evolved from L1 → IoU loss → GIoU / DIoU / CIoU. These still give a useful gradient when the boxes don't overlap, and they also penalise centre distance and aspect ratio.

Non-maximum suppression (NMS)

🧒 In plain English

A detector fires many overlapping boxes on the same object. NMS cleans up: keep the most confident box, delete every box that overlaps it by more than a threshold, then repeat with the next most confident survivor.

NMS live
Two cars, nine raw predictions. Faded boxes are removed. Too low an IoU threshold merges neighbouring cars; too high leaves duplicates.
🎯 Interview point

NMS is hand-tuned, sequential post-processing that adds latency and fails in crowds (two overlapping people get merged). Fixes: Soft-NMS (decay scores instead of deleting), class-aware NMS, or NMS-free detectors. DETR-style models (RT-DETR, D-FINE, RF-DETR) and YOLOv10 / YOLO26 use one-to-one matching, so each object gets exactly one prediction.

mAP: the detection metric

  1. For each class, sort predictions by confidence. A prediction is a true positive if IoU ≥ threshold with an unmatched ground-truth box; otherwise it's a false positive.
  2. Sweep the confidence threshold to trace the precision–recall curve. AP is the area under it (interpolated).
  3. mAP is the mean of AP over classes. mAP@0.5 (PASCAL VOC) is lenient on localisation. mAP@0.5:0.95 (COCO) averages over IoU thresholds 0.5, 0.55, …, 0.95 and rewards tight boxes.
  4. COCO also reports APS/APM/APL for small (<32² px), medium and large objects. Check APS if small objects matter to you.
⚠️ Business ≠ mAP

mAP averages over all thresholds, but production runs at one threshold. Report precision and recall at your operating threshold, per class, and a confusion matrix (including the "background" class), alongside mAP.

Detector families

TWO-STAGE · 2015→

Faster R-CNN (+ FPN)

Stage 1: a Region Proposal Network slides anchors over the feature map and proposes ~1–2k "objectness" boxes. Stage 2: RoIAlign crops features per proposal, then a head classifies and refines each box. FPN adds a top-down feature pyramid for multi-scale objects. Accurate and flexible, but slower. Mask R-CNN adds a mask head.

ONE-STAGE · 2016→

SSD, RetinaNet, YOLO

Predict class + box densely at every grid cell in one pass. RetinaNet introduced focal loss to fix the extreme foreground/background imbalance of dense prediction. YOLO (v1 2016 → YOLOv8 → YOLO11 → YOLO26 in Jan 2026) is the real-time workhorse: anchor-free heads, CSP backbones, mosaic augmentation and a strong training recipe out of the box.

TRANSFORMER · 2020→

DETR family

Treats detection as set prediction: a fixed set of learned object queries attends to image features, and Hungarian matching assigns each ground-truth box to one query during training, so there are no anchors and no NMS. The original DETR trained slowly. Deformable DETR, DINO-DETR, RT-DETR (first real-time DETR, 2023), D-FINE and DEIM (faster convergence) and RF-DETR (DINOv2 backbone, strong domain transfer) closed the gap and now match or beat YOLO on accuracy per latency.

OPEN-VOCABULARY · 2022→

Grounding DINO, OWL-ViT, YOLO-World / YOLOE, SAM 3

Detect classes described in text ("damaged bumper") without training on them. Great for auto-labelling and long-tail categories. Usually fine-tune a closed-set detector on the auto-labels for production speed and accuracy.

✅ Detection improvement checklist, in order of payoff
  1. Label quality: consistent box tightness, no missing boxes (missing labels teach the model that objects are background), clear class definitions. Audit 100 random images by hand.
  2. Representative data: lighting, angles, devices, backgrounds from production. Add hard negatives (look-alike backgrounds) to cut false positives.
  3. Small objects: larger imgsz, tiled inference (SAHI), a high-resolution P2 head, avoid over-downscaling.
  4. Class imbalance: oversample images containing rare classes, focal loss, copy-paste augmentation.
  5. Model and recipe: bigger variant, longer training, stronger pretrained backbone, EMA weights.
  6. Inference: per-class thresholds, TTA (flip + multi-scale), ensemble with Weighted Boxes Fusion (WBF) for offline jobs.

Segmentation

🧒 In plain English

Segmentation colours in the image instead of boxing it. Semantic: every pixel gets a class ("road", "car"), but two cars share one blob. Instance: each car gets its own mask. Panoptic: both at once.

FCN → U-Net (2015)

An encoder downsamples to learn what, a decoder upsamples to recover where, and skip connections copy fine detail from encoder to decoder. Still the default for medical and industrial images, and works with a few hundred labelled images.

DeepLabv3+ (2018)

Atrous (dilated) convolutions enlarge the receptive field without losing resolution. ASPP pools context at several dilation rates. Strong for scenes and satellite imagery.

Mask R-CNN (2017)

Faster R-CNN plus a small mask head per box, using RoIAlign for pixel accuracy. The classic instance-segmentation model.

SegFormer / Mask2Former (2021)

Transformer encoders with light decoders. Mask2Former handles semantic, instance and panoptic segmentation in one architecture using masked attention.

SAM → SAM 2 → SAM 3 (2023–25)

Promptable foundation models. SAM takes points or boxes and returns masks. SAM 2 adds video with memory. SAM 3 (Nov 2025) segments every instance of a text concept ("shipping container") in images and video. Use them for auto-labelling, then distil into a small task model.

📐 Segmentation losses

Pixel BCE / cross-entropy: per-pixel classification, dominated by the background when objects are small. Dice loss = 1 − 2|P∩G| / (|P| + |G|) optimises overlap directly and is robust to imbalance. BCE + Dice is the usual default. Use Focal or Tversky to weight false negatives more (lesions, cracks). Metrics: IoU (Jaccard) and Dice, with Dice = 2·IoU / (1 + IoU).

Pose, tracking, OCR and similarity

Pose / keypoints

Predict heatmaps per keypoint (HRNet keeps high resolution throughout) or regress keypoints with the box (YOLO-pose, RTMPose). Metric: OKS-based AP. Use: liveness detection ("turn your head"), fitness, ergonomics.

Multi-object tracking

Tracking-by-detection: run a detector per frame, predict motion with a Kalman filter, associate boxes across frames with the Hungarian algorithm on IoU and appearance embeddings (DeepSORT). ByteTrack also associates low-confidence boxes, which reduces ID switches during occlusion.

OCR pipeline

(1) Text detection (DBNet, CRAFT) finds text regions. (2) Recognition turns crops into strings: CRNN (CNN + BiLSTM + CTC loss, which aligns unsegmented sequences) or transformer TrOCR. (3) Layout and key–value extraction: LayoutLMv3 (text + position + image), Donut (OCR-free), or a vision-language model. Metric: character error rate (CER).

Similarity & verification

Learn an embedding where same-identity images are close. Triplet loss (anchor, positive, negative with a margin), contrastive, or ArcFace (additive angular margin on a normalised softmax, the face-recognition standard). Serve with ANN search. Metric: TAR at a fixed FAR (e.g. 1e-4) for e-KYC face match.

Interview Q&A

One-stage vs two-stage detectors?

Two-stage (Faster R-CNN) first proposes regions, then classifies and refines each. It's more accurate on small or crowded objects but slower. One-stage (YOLO, RetinaNet) predicts densely in one pass. It's faster but faces extreme foreground/background imbalance, which focal loss and better label assignment address. Modern one-stage and DETR models have largely closed the accuracy gap.

Explain NMS and its weaknesses.

Sort by score, keep the top box, suppress boxes with IoU above a threshold, repeat. Weaknesses: one hand-tuned threshold, it suppresses true neighbours in crowds, and it's sequential post-processing that adds latency. Alternatives: Soft-NMS, WBF for ensembles, NMS-free models with one-to-one matching (DETR, YOLOv10/YOLO26).

What is Hungarian matching in DETR?

DETR outputs a fixed set of N predictions. During training, the Hungarian algorithm finds the one-to-one assignment between predictions and ground-truth objects that minimises a cost (class probability + L1 + GIoU). Unmatched predictions are trained to predict "no object". Because each object maps to exactly one query, there are no duplicates and no NMS.

mAP@0.5 vs mAP@0.5:0.95?

mAP@0.5 counts a detection correct at IoU ≥ 0.5, which is lenient on localisation. COCO mAP averages AP over IoU thresholds 0.5 to 0.95 in steps of 0.05, so it rewards precise boxes. If mAP@0.5 is high but mAP@0.5:0.95 is low, the model finds objects but boxes them loosely.

Your detector misses small objects. What do you do?

Increase input resolution or use tiled inference (SAHI), use an FPN or an extra high-resolution P2 head, check anchors (if anchor-based), avoid augmentations that shrink objects further, oversample small-object images, and confirm the labels actually include small instances. Measure APS specifically.

Too many false positives on background. Fixes?

Add hard-negative images (background-only images that look similar), raise or tune per-class confidence thresholds, check for label noise (unlabelled objects confuse the model), add a classifier as a second-stage verifier, and collect more diverse backgrounds.

Dice vs IoU, and why Dice loss?

Both measure overlap; Dice = 2·IoU/(1+IoU), so Dice is always ≥ IoU. Dice loss directly optimises overlap and isn't swamped by the many background pixels the way per-pixel cross-entropy is, so it's preferred for small foreground objects. In practice you combine it with BCE for stable gradients.

Why does U-Net need skip connections?

Downsampling discards spatial detail. The decoder knows what is there but not exactly where. Skip connections pass high-resolution encoder features straight to the matching decoder level, so boundaries come out sharp.

How would you build e-KYC face matching?

Detect and align the face on the ID card and on the selfie (landmarks), embed both with an ArcFace-type model, compare cosine similarity against a threshold chosen for a target false-accept rate (e.g. 1e-4), and add a liveness / anti-spoofing model (passive texture CNN or active challenge). Monitor performance across demographic groups for fairness, and keep a human-review band near the threshold.

How would you label 50,000 images cheaply?

Bootstrap with foundation models: open-vocabulary detection (Grounding DINO, YOLOE, SAM 3) or SAM for masks. Have humans review and correct a stratified sample. Train a task model, then use active learning (label the images where the model is least certain) for the next rounds. Track label quality with inter-annotator agreement.
