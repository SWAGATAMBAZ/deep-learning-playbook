Sequence models: RNN, LSTM, GRU

When order matters (a customer's last 50 transactions, a clickstream, a sentence), you need a model with memory. RNNs were the first answer, LSTMs fixed their forgetfulness, and transformers have since replaced them in most places. Interviewers still love the "why LSTM over RNN" question.

Vanilla RNN: a loop with memory

🧒 In plain English

Read a sentence one word at a time while keeping a running "summary" in your head. At each word, you update the summary using the new word and the old summary. That summary is the hidden state. The same update rule (the same weights) is used at every step.

📐 The recurrence
ht = tanh(Wh ht−1 + Wx xt + b)    ŷt = Wy ht

Training unrolls the loop over time and runs ordinary backprop through it. This is called Backpropagation Through Time (BPTT). Long sequences are often cut into chunks (truncated BPTT).

Why vanilla RNNs forget: vanishing gradients

How much does step 1 still influence step T?
The gradient flowing back k steps is multiplied by about (w · tanh′)k in an RNN. In an LSTM, the cell-state path is multiplied by the forget gate f instead, which the model can learn to keep near 1.
🎯 Interview point

Exploding gradients (|w| > 1) are fixed with gradient clipping. Vanishing gradients (|w| < 1) need an architecture change: LSTM/GRU gates, residual connections, or attention.

LSTM: a conveyor belt with three gates

🧒 In plain English

Picture a conveyor belt (the cell state) running through time. Information can ride it for a long way unchanged. Three valves control it: the forget gate decides what to throw off the belt ("the user changed city, so drop the old location"), the input gate decides what new information to put on, and the output gate decides what to reveal as this step's output. Because the belt is updated by adding rather than repeated multiplying, gradients survive over long distances.

📐 The equations (σ = sigmoid, outputs 0–1 "valves")

ft = σ(Wf[ht−1, xt] + bf)  — forget gate
it = σ(Wi[ht−1, xt] + bi)  — input gate
c̃t = tanh(Wc[ht−1, xt] + bc)  — candidate memory
ct = ft ⊙ ct−1 + it ⊙ c̃t  — additive update (the key)
ot = σ(Wo[ht−1, xt] + bo),   ht = ot ⊙ tanh(ct)

Parameters: 4 × (hidden·(hidden + input) + hidden). The "4" is the three gates plus the candidate.

GRU: the lighter LSTM

A GRU merges the cell and hidden state and uses two gates: an update gate z (how much to keep the old state, a combined forget and input) and a reset gate r (how much past to use when computing the candidate). It has about 25% fewer parameters than an LSTM, trains faster, and performs similarly on most tasks. Try a GRU first when data is limited.

Useful variants

Bidirectional

One RNN reads forwards and another backwards, then their states are concatenated. Good for NER and classification when the full sequence is available. Not usable for real-time forecasting.

Stacked

2–3 RNN layers on top of each other. More than that rarely helps.

Seq2Seq (encoder–decoder)

The encoder compresses the input into a context and the decoder generates the output. Its fixed-size bottleneck led to attention, and attention led to transformers.

1D CNN / TCN

Causal dilated convolutions over time. They run in parallel and are often as good as LSTMs for forecasting and event sequences.

When to use RNNs today

✅ Practical guidance
  • Streaming / on-device / low latency: the RNN state updates in O(1) per new event. Good for real-time fraud scoring on each new card swipe.
  • Small or medium sequential data: GRU/LSTM are cheaper and less data-hungry than transformers.
  • Long text, big data, or anything that benefits from pretraining: use transformers.
  • Modern alternatives are state-space models (Mamba), which have RNN-like inference cost with transformer-like quality on long sequences. Worth one sentence in an interview.
🏦 Industry example: transaction-sequence fraud

Each card's last N transactions (amount, MCC embedding, time-delta, country, channel) go into a GRU. The final hidden state is a "behaviour fingerprint". Concatenate it with the current transaction's features and score fraud. A sudden overseas high-value purchase after a history of small local ones looks anomalous relative to that customer, which a per-row model cannot see.

Interview Q&A

Why do vanilla RNNs suffer from vanishing gradients, and how does LSTM fix it?

BPTT multiplies the same Jacobian (Wh·tanh′) at every step, so over k steps the gradient scales like λk and vanishes if λ<1. LSTM's cell state is updated additively, ct = f·ct−1 + i·c̃, so ∂ct/∂ct−1 ≈ f. The model can learn f≈1 to carry information (and gradients) across long gaps: the "constant error carousel".

LSTM vs GRU: which would you pick?

They're usually within noise of each other. A GRU has fewer parameters, trains faster and suits smaller data. An LSTM's separate cell state can help on very long dependencies. Try both if cheap; otherwise default to GRU, or move to a transformer for large data.

Why did transformers replace RNNs?

(1) Parallelism: RNNs process tokens one after another, while attention handles the whole sequence at once, so training on GPUs is much faster. (2) Long-range dependencies: any two tokens are one attention hop apart instead of T steps apart. (3) They scale with data and pretraining. The cost is O(n²) memory in sequence length.

What's teacher forcing?

When training a seq2seq decoder, you feed the ground-truth previous token as input instead of the model's own prediction. It speeds up convergence but creates exposure bias (at inference the model sees its own mistakes). Scheduled sampling mixes the two.

How do you handle variable-length sequences in a batch?

Pad to the batch maximum with a padding index, then use pack_padded_sequence (or masks for transformers) so padding doesn't affect the state or the loss. Bucket sequences of similar length together to reduce wasted padding.
