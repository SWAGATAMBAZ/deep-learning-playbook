LSTM in depth

The LSTM (Hochreiter & Schmidhuber, 1997) fixed the vanilla RNN's amnesia by adding a separate cell state and three learnable gates that decide what to forget, what to write and what to reveal. It was the default sequence model for two decades and still powers many streaming and on-device systems.

The problem LSTM solves

🧒 In plain English

"The customer, who opened her account in Pune in 2019 and has since made hundreds of small UPI payments, salary credits and bill payments, just made a card purchase in São Paulo." To flag this you must remember Pune across hundreds of steps of irrelevant activity. A vanilla RNN overwrites its memory at every step, so after ~10–20 steps the early information (and its gradient) is gone. The LSTM adds a protected memory lane that keeps information until the model decides to drop it.

Intuition: a conveyor belt with three valves

memory lane

Cell state ct

A conveyor belt running through time. Information rides along mostly unchanged; it's only scaled (forgotten) and added to (written). This is long-term memory.

working memory

Hidden state ht

A filtered read-out of the belt that is passed to the next step and to the output layer. This is short-term, "what's relevant right now".

valve 1

Forget gate ft

"What should I erase from the belt?" 1 = keep everything, 0 = wipe. E.g. the customer changed city, so drop the old city.

valve 2

Input gate it + candidate gt

"Is this step worth writing down, and what exactly?" g proposes new content; i decides how much of it to add.

valve 3

Output gate ot

"Which part of memory matters for the current decision?" Controls what the belt reveals as ht.

key idea

Add, don't overwrite

A vanilla RNN replaces its state each step. An LSTM adds to its cell state. Addition passes gradients through unchanged, multiplication shrinks them.

The equations, gate by gate

📐 One LSTM step (σ = sigmoid → 0..1 valves, tanh → −1..1 content)

ft = σ(Wf xt + Uf ht−1 + bf)
it = σ(Wi xt + Ui ht−1 + bi)
gt = tanh(Wg xt + Ug ht−1 + bg)   (often written c̃t)
ot = σ(Wo xt + Uo ht−1 + bo)
ct = ft ⊙ ct−1 + it ⊙ gt
ht = ot ⊙ tanh(ct)

⊙ = element-wise product. All four "gates" read the same inputs [xt, ht−1], so in code they are computed as one big matrix multiply and split into four chunks. PyTorch's order is i, f, g, o.

Why gradients survive in an LSTM

📐 The constant error carousel
∂ct / ∂ct−1 = ft  (+ smaller indirect terms through ht−1)

Along the cell path, the gradient back k steps is roughly the product of forget gates ft·ft−1·…, with no squashing tanh′ and no repeated Whh multiplication. If the model keeps f ≈ 1 for information it needs, the gradient flows almost undiminished. That's why initialising the forget-gate bias to 1 (so f ≈ 0.73 at the start) helps the LSTM learn long dependencies from the first epoch (Gers et al., 2000; Jozefowicz et al., 2015).

LSTMs can still explode through the h-path, so you still clip gradients. They reduce vanishing a lot but don't make memory infinite: dependencies of hundreds of steps are feasible, thousands are hard.

Parameter count: 4× a vanilla RNN

📐 Formula
params per layer per direction = 4 × (I·H + H·H + 2H)

Worked example: I = 32, H = 128, 1 layer → 4 × (4,096 + 16,384 + 256) = 82,944. The 4 is the three gates plus the candidate. PyTorch stores two bias vectors (bih and bhh), hence 2H.

Variants you should know

Peephole LSTM

Gates also look at the cell state ct−1. It helps with precise timing tasks; rarely used today (not in cuDNN).

CIFG / coupled gates

Ties the input gate to (1 − forget gate): "only write as much as you forget". Fewer parameters, similar accuracy. It's the idea that leads to the GRU.

Bidirectional & stacked LSTM

BiLSTM for offline tagging (NER, BiLSTM-CRF), 2–3 layers for capacity.

Encoder–decoder LSTM

Seq2seq for translation and multi-step forecasting. Add attention over the encoder outputs to remove the bottleneck.

ConvLSTM

Gates use convolutions instead of matrix multiplies, so the state is an image-like grid. Used for precipitation nowcasting and video frames.

LSTM autoencoder

Encode a sequence into hT and reconstruct it. Reconstruction error flags anomalous sequences (sensor faults, account behaviour).

AWD-LSTM

Regularisation recipe: DropConnect on the recurrent weights, variational dropout, NT-ASGD. It was the strongest LSTM language model before transformers.

xLSTM (2024)

A modern revival with exponential gating and matrix memory (sLSTM/mLSTM), positioned as a linear-time competitor to transformers. Good to mention to show you know the field.

How to improve LSTM performance

✅ Checklist, roughly in order of payoff
  1. Better inputs: per-step features with signal (log amount, embeddings for categoricals, time since the previous event, hour/day cycles as sin/cos). Normalise numerics.
  2. Right window: test several lookbacks; aggregate very old history into summary features instead of making the sequence longer.
  3. Correct last-state extraction with packing (see bugs below). This often "fixes" a mysteriously weak model.
  4. Stabilise training: gradient clipping, forget bias 1, orthogonal init, LR schedule (ReduceLROnPlateau / cosine), early stopping.
  5. Regularise: dropout on embeddings, between layers and before the head; weight decay; variational/weight dropout for language-model style tasks.
  6. Use all hidden states: attention pooling or max+mean pooling over outputs often beats the last state alone for classification.
  7. Combine with static features: concatenate hT with customer-level features (or feed hT into a GBDT).
  8. Imbalance: weighted BCE or focal loss; threshold from the business cost.
  9. Benchmark alternatives: GRU (faster), TCN, transformer, or GBDT on aggregates. Keep the LSTM only if it wins on out-of-time validation.

Interview Q&A

Walk me through the LSTM gates.

All gates read [xt, ht−1]. Forget gate f (sigmoid) scales the old cell state, i.e. what to erase. Input gate i (sigmoid) scales a tanh candidate g, i.e. what new content to add. Cell update ct = f⊙ct−1 + i⊙g. Output gate o (sigmoid) decides what to expose: ht = o⊙tanh(ct).

Why does the LSTM mitigate vanishing gradients?

The cell state is updated additively, so ∂ct/∂ct−1 ≈ ft with no Whh multiplication or tanh′ squashing on that path. If the network learns f ≈ 1 for important information, gradients pass through many steps nearly unchanged (the constant error carousel).

Why sigmoid for gates and tanh for the candidate?

Gates are valves, so they need a 0–1 range that multiplies content (0 = block, 1 = pass). The candidate is content to add, which needs to be signed and bounded (−1..1) so it can increase or decrease memory without blowing up.

Why initialise the forget-gate bias to 1?

With zero bias, f starts around 0.5, so memory halves every step and gradients decay from the start. A bias of 1 makes f ≈ 0.73, so the LSTM remembers by default early in training and can learn long dependencies more easily (Gers et al. 2000; Jozefowicz et al. 2015).

Cell state vs hidden state?

The cell state c is long-term memory, updated additively and not directly exposed. The hidden state h = o⊙tanh(c) is the gated, squashed read-out used as the step's output and fed into the next step's gates.

How many parameters does an LSTM layer have?

4·(I·H + H·H + H) with one bias vector, or 4·(I·H + H·H + 2H) in PyTorch, which keeps two. E.g. I = 32, H = 128 gives 82,944 in PyTorch. It's four times a vanilla RNN because of the three gates plus the candidate.

Can an LSTM still have exploding gradients?

Yes. Paths through ht−1 and the recurrent weights can still amplify. That's why gradient clipping remains standard with LSTMs.

How would you use an LSTM for fraud detection in real time?

Represent each customer's events (amount, MCC embedding, channel, time delta, device) as a sequence. Train a many-to-one LSTM on the last N events before each labelled transaction, using out-of-time validation. In production, keep each customer's (h, c) in a fast store and update it with an LSTMCell as each event arrives (O(1)). Score with a head on h plus current-transaction features, and monitor drift.

LSTM vs transformer: when would you still choose the LSTM?

Streaming or on-device inference with constant memory per step, small or medium data, short-to-moderate sequences, and strict latency on CPU. Transformers win with large data, long-range context, pretraining and parallel training.

What does a BiLSTM-CRF do?

A bidirectional LSTM gives each token context from both sides. A CRF layer on top models dependencies between adjacent labels (e.g. I-PER can't follow B-ORG) and decodes the best label sequence with Viterbi. It was the classic NER architecture before BERT.
