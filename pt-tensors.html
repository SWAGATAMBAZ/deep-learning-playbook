PyTorch I: Tensors & autograd

Everything in PyTorch is a tensor (an n-dimensional array that can live on a GPU) plus autograd (a system that records operations and computes gradients for you). Master these two and every model on this site is just tensors flowing through functions.

Why PyTorch

Pythonic and eager

Code runs line by line like NumPy, so you can debug with print and breakpoints. torch.compile adds compiler speed when you want it.

The ecosystem

Hugging Face, timm, torchvision, Ultralytics, PyG, Lightning and most research code are PyTorch-first.

Interview reality

DS coding rounds increasingly ask you to write a training loop, a custom Dataset, or attention in PyTorch from memory. The drills page trains exactly that.

Broadcasting

🧒 In plain English

PyTorch lets you add a (3,) vector to a (4, 3) matrix without copying it four times. It lines up shapes from the right. Two sizes are compatible if they're equal, or one of them is 1 (that one gets "stretched"). A missing dimension counts as 1.

Broadcasting checker
Try: 8,3,32,32 + 3,1,1 (per-channel normalise) · 64,10 + 64 (the classic bug) · 64,10 + 64,1
⚠️ Silent broadcasting bug

pred shape (64, 1) minus y shape (64,) broadcasts to (64, 64), so your MSE is computed over 4,096 wrong pairs without any error. Always squeeze(-1) predictions or assert pred.shape == y.shape.

Autograd: how gradients happen

🧒 In plain English

When a tensor has requires_grad=True, PyTorch keeps a receipt of every operation done to it: the computation graph. Calling loss.backward() walks the receipts backwards with the chain rule and writes ∂loss/∂parameter into each parameter's .grad. The graph is rebuilt on every forward pass (it's dynamic), which is why plain Python ifs and loops work inside models.

ConceptMeaning
Leaf tensorCreated by you (e.g. parameters). Its .grad is populated after backward.
grad_fnThe backward function attached to non-leaf results (e.g. MulBackward0)
.backward()Only on a scalar, or pass gradient= for non-scalars. Frees the graph afterwards unless retain_graph=True.
Accumulation.grad adds up across backward calls, hence optimizer.zero_grad() each step
torch.no_grad() / torch.inference_mode()Don't record the graph (evaluation, inference). inference_mode is faster but its tensors can't be used in autograd later.
.detach()Same data, cut out of the graph (stop gradients, e.g. target networks, logging)

Interview Q&A

view vs reshape?

view never copies and requires compatible (contiguous) memory; it errors otherwise. reshape returns a view when possible and silently copies when not. Use view when you want a guarantee of no copy.

What does contiguous mean?

The elements are laid out in memory in the order implied by the shape (row-major). permute/transpose only change strides, so the tensor becomes non-contiguous; .contiguous() makes a re-ordered copy.

Why do we call optimizer.zero_grad()?

PyTorch accumulates gradients into .grad on every backward (handy for gradient accumulation and multi-loss setups). Without zeroing, each step uses the sum of all previous gradients.

no_grad vs inference_mode vs detach vs eval?

no_grad/inference_mode are context managers that stop graph recording (inference_mode is stricter and faster). detach cuts one tensor out of the graph. model.eval() changes layer behaviour (dropout off, BatchNorm uses running stats) and doesn't affect gradients. At inference you typically use both eval() and inference_mode().

What is a leaf tensor and why is .grad None on my intermediate tensor?

Leaves are tensors you created with requires_grad (like parameters). Only leaves keep .grad by default. For an intermediate, call t.retain_grad() before backward, or use a hook.

Static vs dynamic computation graph?

PyTorch builds the graph on the fly during each forward pass (define-by-run), so control flow can depend on data and debugging is natural Python. torch.compile/torch.export capture graphs ahead of time for speed and deployment when needed.

When would you write a custom autograd Function?

When an op isn't differentiable or you want a different gradient (straight-through estimator for quantisation, gradient reversal for domain adaptation), or for a memory-efficient handwritten backward. Verify it with gradcheck.
