Generative AI & LLMs

Three generative families, one paragraph each

VAE

Compress → sample → decode

An encoder maps data to a smooth latent distribution and a decoder rebuilds it. Sample the latent to generate. Training is stable, but outputs tend to be blurry. Used for synthetic tabular data and anomaly scores.

GAN

Forger vs detective

A generator makes fakes and a discriminator tries to spot them, and both improve together (a min-max game). Outputs are sharp, but training is unstable and prone to mode collapse (only producing a few kinds of output). CTGAN is used for synthetic tabular data such as rare fraud cases.

Diffusion

Learn to un-noise

Gradually add noise to images until they're pure static, and train a network (usually a U-Net or transformer) to predict and remove the noise at each step. To generate, start from noise and denoise step by step. This powers Stable Diffusion and modern image and video generators. Highest quality, but slower sampling.

How an LLM is built

1 · Pretraining

Next-token prediction

A decoder-only transformer on trillions of tokens. It learns language, facts and reasoning patterns. Extremely expensive.

2 · SFT

Instruction tuning

Fine-tune on (instruction, ideal response) pairs so it follows requests.

3 · Preference tuning

RLHF / DPO

Learn from human (or AI) preference comparisons between answers. RLHF trains a reward model and then uses RL (PPO). DPO optimises directly on the preference pairs. This makes the model helpful and safe.

🧒 In plain English

An LLM is autocomplete trained on a huge library and then coached to be a helpful assistant. It generates one token at a time, each time choosing from a probability distribution over the next token. This is why it can hallucinate: it produces plausible text, not looked-up facts, unless you give it the facts (RAG).

Decoding: temperature, top-k, top-p

Next token after "Your loan application has been …"
Temperature reshapes the distribution. Top-k and top-p cut off the unlikely tail (faded bars can't be sampled).

Use low temperature (0–0.3) for extraction, classification and SQL generation, where you want repeatable answers. Use higher (0.7–1) for creative text. Temperature 0 is close to greedy decoding.

🎯 The one-liner

"RAG for knowledge, fine-tuning for behaviour. I'd start with prompting plus RAG, build an eval set, and fine-tune only if evals show a gap in format, tone or cost that prompting can't close."

RAG: retrieval-augmented generation

INDEX

Chunk → embed → store

Split documents into ~300–800-token chunks with overlap, embed them, and store in a vector DB with metadata.

RETRIEVE

Hybrid search

Dense vectors + BM25 keywords, then re-rank the top candidates with a cross-encoder. Filter by metadata (product, date, region).

GENERATE

Grounded prompt

"Answer only from the context; cite sources; say 'I don't know' if it isn't there."

⚠️ Where RAG fails

Bad chunking (tables split in half), retrieval misses (embedding model unsuited to the domain), too much irrelevant context, stale indexes, and no evaluation. Measure retrieval and generation separately: retrieval with recall@k, generation with faithfulness and answer relevance.

Fine-tuning efficiently: LoRA & QLoRA

🧒 In plain English

Updating all 7 billion weights is expensive. LoRA freezes the original model and learns a small "correction" for selected weight matrices as the product of two thin matrices. You train under 1% of the parameters, the adapter file is a few MB, and you can swap adapters per task.

📐 LoRA
W' = W + ΔW = W + B·A,   B ∈ ℝd×r, A ∈ ℝr×k,   r ≪ d

With d = k = 4096 and r = 8: the full matrix has 16.7M parameters, LoRA has 65k (0.4%). QLoRA also stores the frozen base model in 4-bit, so you can fine-tune a 7–13B model on one consumer GPU.

Evaluating LLM systems

  • Golden set: 100–500 real questions with reference answers, labelled by domain experts. Run it in CI on every prompt or model change.
  • Task metrics where possible: exact match, F1 for extraction, accuracy for classification.
  • LLM-as-judge with a rubric for open-ended answers (faithfulness, relevance, tone). Calibrate the judge against human labels.
  • Ops metrics: latency (p95), cost per request, refusal rate, PII leakage, prompt-injection robustness.
  • Online: thumbs up/down, deflection rate (chatbot), handle-time reduction, CSAT.

Interview Q&A

GAN vs VAE vs diffusion?

VAE: likelihood-based, stable, smooth latent space, blurrier samples. GAN: adversarial, sharp samples, unstable training and mode collapse. Diffusion: iterative denoising, best quality and diversity with stable training, but slower sampling (mitigated by fewer-step samplers and distillation).

What is hallucination and how do you reduce it?

Fluent but false or unsupported output. Reduce it by grounding with RAG and requiring citations, using low temperature, constraining output (JSON schema, enums), instructing the model to say "I don't know", verifying with a second pass or tools, and measuring faithfulness on an eval set.

Why does LoRA work?

Weight updates during fine-tuning tend to have low intrinsic rank. Most of the useful change lives in a small subspace, so ΔW ≈ BA with small r captures it. Benefits: far less memory (no optimizer state for frozen weights), small adapters, no added inference latency once merged.

RLHF vs DPO?

RLHF trains a reward model from preference pairs and then optimises the policy with PPO plus a KL penalty to the SFT model. It's powerful but complex and unstable. DPO gets the same objective in closed form as a classification-style loss directly on preference pairs, with no reward model and no RL loop. It's simpler and widely used.

A bank wants a chatbot over 2,000 policy PDFs. Outline it.

Ingest with layout-aware parsing (tables!), chunk with metadata (product, version, date), hybrid retrieval + re-ranker, an LLM with a grounded prompt and citations, guardrails (PII masking, refusal on advice outside scope, prompt-injection filtering), human handoff, a golden eval set with retrieval and faithfulness metrics, logging, and an index-refresh pipeline when policies change. Choose a model that meets data residency rules.

How do you reduce LLM cost and latency?

Use smaller models (route easy queries to small, hard to large), prompt caching, shorter prompts and contexts, batching, quantisation (INT8/4-bit) for self-hosted models, distillation into a fine-tuned small model, streaming responses, and caching frequent answers.
