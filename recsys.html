The industry funnel (draw this first in any design round)

STAGE 1 · millions → ~1000

Candidate generation

Fast and recall-oriented. Two-tower ANN retrieval, item-to-item co-visitation, popular-in-category, "buy it again".

STAGE 2 · 1000 → 100

Ranking

A heavy model with rich user × item × context features predicts P(click), P(buy). DCN, DLRM, DIN, or GBDT.

STAGE 3 · 100 → 20

Re-ranking

Business rules: diversity, freshness, dedup, sponsored slots, stock and margin, fairness.

🧒 Why a funnel?

You can't run a heavy neural ranker over 50 million products in 100 ms. So a cheap net catches the plausible fish, and an expensive net picks the best of those.

Collaborative filtering & matrix factorisation

🧒 In plain English

"People like you also liked…". Put users as rows and items as columns in a giant, mostly empty table of interactions. Matrix factorisation guesses the blanks by giving each user and each item a short taste vector, with dimensions like "likes budget electronics" or "premium fashion", so that user·item ≈ rating. The taste dimensions are learned, not hand-labelled.

📐 Objective
min Σ(u,i)∈observed (rui − pu·qi − bu − bi)² + λ(‖p‖² + ‖q‖²)

With implicit feedback (clicks and purchases, no ratings), unobserved ≠ disliked. Use BPR loss (rank observed items above sampled negatives) or weighted ALS. Neural CF (NCF) swaps the dot product for an MLP over the two embeddings, though a well-tuned dot product is often just as good.

Two-tower retrieval

Two-tower scoring: user vector · item vector
The user tower turns behaviour into a taste vector, and the item tower does the same for products. The score is a dot product. Move the user's tastes and watch the ranking change instantly. This is why retrieval is fast: item vectors are precomputed.
  • User tower: user ID embedding + recent-history embeddings (pooled or GRU/transformer) + context (time, device, location).
  • Item tower: item ID + category + brand + price + text/image embeddings. Content features help cold-start items.
  • Training: softmax over in-batch negatives (other users' positives act as negatives), with a correction for popularity bias in sampling.
  • Serving: precompute all item vectors, index them in FAISS/ScaNN, compute the user vector per request, and run ANN search for the top-k in milliseconds.

Sequential / session recommenders

Treat a session's clicks like a sentence and predict the next item. GRU4Rec (RNN), SASRec (causal transformer, next-item), and BERT4Rec (masked-item prediction). These are strong when users are anonymous or intent shifts within a session ("now shopping for shoes").

Cold start, feedback loops and bias

New user

Popular-in-region, onboarding questions, context features (device, location, referrer), session-based recommendations from the first click.

New item

Content features in the item tower (text, image, category, price), exploration slots (bandits), boosting freshness.

Position bias

Top slots get clicked anyway. Add position as a training feature and set it to a constant at serving time, or use inverse propensity weighting.

Feedback loop / popularity bias

The model only learns from what it showed. Mitigate with exploration (ε-greedy, Thompson sampling), logQ correction and diversity re-ranking.

Interview Q&A

Design "Recommended for you" for an e-commerce home page.

Clarify the objective (CTR vs GMV vs long-term retention) and the latency budget. Build a multi-source candidate generation stage: two-tower ANN, co-purchase item-to-item, recently viewed, trending in segment. Then a ranker (DCN/DLRM or LightGBM) with user, item, context and cross features, predicting P(click) and P(purchase) via multi-task learning. Re-rank for diversity, stock, business rules. Use time-split offline evaluation (Recall@K, NDCG), then an online A/B test on GMV/session with guardrails. Cover cold start, position bias and a monitoring and retraining cadence.

Why in-batch negatives, and what's the bias?

They're free: the other positives in the batch serve as negatives, so you get many negatives per step at no extra cost. But popular items appear more often as negatives, so they get unfairly pushed down. Apply the logQ correction (subtract log of the item's sampling probability from the logit) or mix in uniformly sampled negatives.

Explicit vs implicit feedback?

Explicit feedback means ratings: sparse, but with clear signal including negatives. Implicit means clicks, views, purchases: abundant but noisy, with no true negatives (not clicked might mean not seen). Implicit needs ranking losses (BPR, sampled softmax) and careful negative sampling.

Offline NDCG improved but the A/B test was flat. Why?

Common reasons: offline data is biased by the old model's exposure (counterfactual problem), the metric doesn't match the business goal, train/serve skew in features, latency increased, novelty effects, or the gains were on segments that don't drive revenue. Check logging and feature parity first.

How do you recommend a credit card or loan product in a bank?

The catalogue is small, so it's a propensity / uplift problem rather than retrieval: a multi-label or per-product classifier (GBDT or multi-task NN) on transaction and demographic features, plus eligibility rules and risk filters. Use uplift modelling to target people the offer actually changes, and add fairness and regulatory checks.
